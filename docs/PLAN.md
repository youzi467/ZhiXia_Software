## 0. 产品定位

一套 **Android 端配套软件**，服务于已有的智侠硬件开发板：开发板板载大模型，以**手机摄像头采集的画面**作为视觉输入，识别结果由**硬件侧呈现**（语音读出 + 板载小屏显示）。

```
[ 手机摄像头 ]              [ 开发板 (Linux/ARM) ]           [ 云端 ]
     │ 拍照/选图                板载大模型(本地) 或 ──转发──► 云模型
     ▼ 压缩后单张上传 ───────── WiFi / mDNS 发现 ──► 识别结果(语音+小屏)
   只确认"网络送达" ──►        （手机端不展示模型结果）
```

- **目标用户**：开发测试人员 + 未来终端用户兼顾
- **发布形态**：Debug 开发包
- **平台**：仅 Android

## 1. 目标 / 非目标（Scope）

### 1.1 在本期范围内（In scope）
- 仅 Android；原生 Kotlin + CameraX + 网络
- 通信：当前阶段**仅传单张照片**（非视频流），走 WiFi
- 手机四个职责：
  1. 实时取景、拍照；或相册选图
  2. 照片压缩后，WiFi 上传单张
  3. 仅确认「网络送达」给用户
  4. 本地保存发送历史
- 板卡自动发现：局域网 mDNS/Bonjour
- 本地 / 云端：两种都支持，但**由板卡自动决定，手机端无切换入口**
- 云端路由：板卡把照片转发给云模型
- 协议：由软件侧设计（建议 HTTP + JSON），硬件侧配合实现
- 异常处理：基础即可 — 板卡离线 / 超时 / 发送失败，提示并重试
- 设置持久化：轻量，记住上次连接的板卡

### 1.2 明确不做（NOT in scope）
- 视频流 / 实时摄像头推流
- 手机端展示模型识别结果（结果呈现完全在硬件侧）
- 手机端本地 / 云端切换入口
- 云端认证、账号体系（本期）

### 1.3 延期（Defer，记录到 TODOS）
- 多板卡管理、板卡重命名（初版仅"记住上次连接"）
- 批量/队列上报、断点续传
- 结果回传手机上（若后续需求演进）

## 3. 核心数据流（单张照片）

```
拍照/选图 ─► 压缩 ─► 找板卡(缓存/发现) ─► POST /image ─► 收到ACK ─► "已送达·处理中"(计时) ─► 记历史
   │          │         │                    │                     │
   │          │         └(离线)━┐            └─► 超时/拒收 ─► 提示错误 ─► 重试/放弃
   │          │                  └─► "未发现板卡" ─► 重试                       └─► 记历史(失败)
   │          └(压缩失败)─►提示错误
   └(未授权/取不到图)─►提示错误
```

失败路径统一写清楚：**误差类 / 触发条件 / 处理 / 用户看到什么 / 测试点**（见 §7）。

## 4. 网络与通信协议（定稿，待硬件侧确认）

- **发现**：手机发起约定的 mDNS/Bonjour 服务查询（如 `_ztimage._tcp`），取板卡 IP 与端口。
- **传输**：HTTP + `multipart/form-data`（工程评审定稿）。
- **ACK 语义**：POST **入队即返回**「已接收」，**不**阻塞到模型处理完（工程评审定稿）。

**请求** `POST /image`（multipart/form-data）：
```http
POST /image HTTP/1.1
Content-Type: multipart/form-data; boundary=...

--boundary
Content-Disposition: form-data; name="request_id"
<uuid>

--boundary
Content-Disposition: form-data; name="source"
camera|gallery

--boundary
Content-Disposition: form-data; name="timestamp"
1727606400

--boundary
Content-Disposition: form-data; name="image"; filename="shot.jpg"
Content-Type: image/jpeg
<jpeg bytes>

--boundary--
```

**响应** `200 OK`：仅表示**网络送达 / 已被板卡接收（入队）**，不含识别结果：
```json
{ "status": "received", "request_id": "..." }
```

**约定**
- 成功 = 2xx → UI 进入「已送达·处理中」；非 2xx / 超时 / 网络异常 → 失败路径。
- `request_id`（UUID）用于**幂等**：重试沿用同一 id，避免板卡端重复入队。
- 响应**不得承载识别结果**（结果由硬件侧呈现），手机端忽略即可。
- 具体字段与错误码由本设计 + 硬件侧协商标定，写入最终 SPEC。

## 5. 手机端四职责实现要点

| 职责 | 实现 | 备注 |
|---|---|---|
| ①取景拍照 / 相册选图 | CameraX `ImageCapture`；`MediaPicker` | 相册 / 拍照入口 |
| ②压缩后 WiFi 上传单张 | 边解码边降采样到**最长边 1280px** + JPEG 质量降到 **80%**，目标体积封顶（如 ~1.5MB，超限进一步降质）| 控制带宽（默认值定稿，可调） |
| ③仅确认「网络送达」 | ACK 状态机：发送→等待→成功/失败 | **不接收/不展示识别结果**；成功后 UI 显示「已送达·处理中」+ 已耗时，供测试者判断板卡在跑（CEO 第 1 轮新增） |
| ④本地保存发送历史 | Room / DataStore 存记录（时间、来源、成功与否） | 轻量 |

### 5.1 UI / 交互（设计第 3 轮定稿）

- **主交互 = 两步**：取景 → 拍照 → 预览 → 「确认发送」。
- **状态呈现 = 顶部常驻状态栏**：显示「已送达·处理中 + 已耗时(mm:ss)」，不打断取景。
- **收尾**：处理中计时到点（默认 **15s** 封顶）后自动转「请在板卡查看结果」提示，并回到取景。
- **离线态**：主界面始终为取景，「未发现板卡 · 点此重试」横幅置于顶部，不禁拍（发送阶段才真正校验并报错）。
- 主界面三个区：取景/预览区、顶部状态栏、下方「相册」+「拍照」入口。

## 6. 板卡发现与连接

- 启动 / 「重连」时做 **mDNS/Bonjour 扫描**，离线板卡不会出现在列表。
- 设置**持久化上次连接**板卡：优先直连上次地址；失败回退到再次扫描。
- 手机端**不暴露本地/云端切换** —— 由板卡决定走本地模型还是转发云端。

## 7. 异常处理映射（错误根因图）

| 误差类 | 触发条件 | 处理 / 用户看到 | 测试点 |
|---|---|---|---|
| `BOARD_OFFLINE` | mDNS 查不到 / 上次地址不可达 | 提示"未发现板卡"，点击重试 | 断开局域网测 |
| `BOARD_UNREACHABLE` | 发现但连接/握手失败 | 提示"板卡不可达" + 重试 | 板卡断电测 |
| `UPLOAD_TIMEOUT` | POST 超时（默认 **10s**） | 提示“发送超时，重试?” | 弱网测试 |
| `UPLOAD_REJECTED` | 非 2xx | 提示错误码 + 重试 | mock 500 |
| `IMAGE_READ_FAIL` | 相册权限/解码失败 | 提示"无法读取图片" | 撤销权限测 |
| `COMPRESS_FAIL` | 图片异常 | 提示错误 | 超大图测 |

- 目标：**零静默失败** —— 每条失败都让用户可见、可重试、可记录。
- 基础即可：不做自动队列/断点续传（Defer）。

## 8. 设置持久化

- **轻量**：仅记住「上次连接板卡」（地址 / 名称 / 时间戳）。
- 实现：Jetpack DataStore（现代、异步），不进 Room。
- 无账号、无云端同步（NOT in scope）。

## 9. 测试策略（草）

- **单元**：压缩逻辑、ACK 状态机、历史记录、错误分类。
- **集成**：mDNS 发现、HTTP 送达（mock 板卡或真机打桩）。
- **手工**：真机 + 板卡联调；弱网 / 断网 / 板卡断电场景（对齐 §7）。
- 目标：错误路径测试 ≥ 正常路径。
